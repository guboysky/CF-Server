# 详情数据核对记录

资源入口默认 6H，首次进入网络延迟默认 24H；四个事实面板取消固定最小高度，桌面实测约 154px，保持四栏对齐和手机单列。

| 项目 | 来源与单位 | 核对结果 |
|---|---|---|
| CPU | cpu，百分比；load_avg 仅为负载，不当作 CPU 百分比 | 历史/实时原值，100% 峰值不再生成 200% 纵轴 |
| RAM / Swap / 磁盘 | *_used / *_total 为 MiB，转换为字节绘图 | 保留有效 0，缺失显示 —；容量变动不会截断较高的历史有效值 |
| 网速 | net_in_speed / net_out_speed，字节/秒 | 下行/上行不对调；对数图、悬浮值与 API 一致 |
| 本月流量 | *_monthly 字节、traffic_limit GiB | 按 dl/ul/max/total 计算；不代替今日或窗口流量 |
| 今日流量 | 后端 daily 字段，或本机已观测计数差值 | 保留起点/partial 标记；程序端补丁仍需更新后生效 |
| 窗口流量圆环 | 仅使用该历史响应的 net_rx/net_tx 计数器差值 | 当前 CF 历史未提供这两列时显示“未提供窗口计数”和 —，不误显示 0；重置后从新计数器继续累计 |
| TCP / UDP / 进程 | tcp_conn / udp_conn / processes，个数 | 分别绘制，缺失不伪造零值 |
| Disk IO | 实时 disk 对象/JSON，或历史 disk_read_bps 等扁平列 | 两种格式均兼容；B/s、IOPS、ms、% 单位分别处理 |
| GPU | gpu_info JSON/数组；info %、mem_used MiB、sm_clock MHz、power W | 按 GPU id 对应历史；零利用率有效，缺失指标不生成曲线 |
| 延迟 / 丢包 | ping_* 毫秒、loss_* 百分比 | 三网同时间戳悬浮值与 API 相符；0 保留，禁用/缺失留空，超时不伪造成 100% 丢包 |
| 覆盖条 / 热力图 | 选中范围划分 24 个互斥时段 | 终点为当前时间，离线尾部无采样留空；不等同精确 SLA，不再把 6H 标作 24-Hour |

实时详情使用批内每个真实样本，不再只绘制批内末个值，也不把保留的旧快照字段复制成新历史。历史请求期间收到的样本在返回时合并；每个范围最多保留 2000 个真实点，超限保留首尾和主要 CPU/网络/延迟等极值，再均匀抽样，避免长会话逐渐丢掉整个较早窗口。统计是保留采样点的均值/峰值，不是连续计费或时间加权统计。

图表断线阈值以初始历史采样间隔为基准，避免密集 WS 点把较稀疏的历史错误断开。多日坐标附日期，CPU、内存、网速、磁盘及三网悬浮值逐时间戳对照实际公开 API。真实站点 Windows/Linux 节点均通过；资源 6H 和延迟 24H 各一条历史请求，未增加轮询或每图请求。截图和原始真实节点数据未入库。

27 项单元测试和 17 项浏览器测试通过，包括 MiB/字节换算、零值/缺失、扁平磁盘指标、批内峰值、长会话历史范围、时间轴、四种公开/验证模拟组合、移动端溢出和请求数量。未提供的指标只能确认展示为缺失，不能证明机器端采集本身准确；历史采样间未上报的瞬时波动无法还原。
